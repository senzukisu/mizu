# Архитектура Mizu

## Выбор движка

| Вариант | Совместимость | Кодеки | Обновления и безопасность | Размер | Решение для 0.1 |
|---|---|---|---|---|---|
| **WebView2** (Edge/Chromium) | Актуальный Chromium | **H.264 и AAC лицензированы Microsoft**; HEVC/AC-3 — через системные декодеры | Вечнозелёная среда, обновляется через Windows Update | Среда общая с ОС, мы её не поставляем | **Выбран** |
| CEF | Актуальный Chromium | В стандартных сборках **нет H.264/AAC**; для проприетарных нужно своё патентное лицензирование | На каждое исправление безопасности нужно пересобирать и раздавать Chromium (~250 МБ) | Большой | Рассмотрим для других платформ (0.7) |
| Servo | Развивается, для ежедневной работы рано | Ограничены | Молодой | Маленький | Следим |
| Tauri/wry | Обёртка над теми же системными WebView | Как у основы | Как у основы | Маленький | Слишком высокий уровень: нет нужного контроля загрузок, разрешений, профилей, перехвата запросов и расширений |

WebView2 даёт Mizu многопроцессную песочницу Chromium и изоляцию сайтов, постоянные обновления безопасности и
лицензированные кодеки. При этом сам Mizu остаётся небольшой нативной программой. Всё, что связано с движком,
собрано в одном крейте (`mizu-engine`), поэтому позже за тем же интерфейсом можно добавить другой движок.

## Крейты

```
crates/
├── mizu-core         идентификаторы, разбор адресной строки, пути профиля, реестр внутренних страниц (без Windows)
├── mizu-settings     схема настроек, значения по умолчанию, проверка, атомарное сохранение TOML
├── mizu-storage      SQLite: история, закладки, загрузки, разрешения, сеанс, пароли; миграции, копии, восстановление
├── mizu-tabs         модель полосы вкладок (порядок, закрепление, закрытые вкладки, снимки) — чистая логика
├── mizu-privacy      Mizu Shield: движок adblock-rust, списки фильтров и их обновление, разрешения, статистика
├── mizu-userscripts  Mizu Scripts: разбор метаданных, шаблоны адресов, правила сайтов, хранилище, API GM_*
├── mizu-media        диагностика медиа (декодеры Media Foundation, видеокарты DXGI)
├── mizu-ui           протокол интерфейса (типизированные JSON-команды и события) и вшитые HTML/CSS/JS
├── mizu-engine       единственный крейт, работающий с WebView2/COM: Engine, View, Download, события
├── mizu-update       подписанный манифест выпуска: проверка ed25519, SHA-256, сравнение версий; утилита mizu-sign
├── mizu-setup        MizuSetup.exe: установка и удаление для пользователя, браузер вшит внутрь
└── mizu-browser      само приложение: окна, вкладки, всплывающие панели, пароли, обновления, данные страниц
assets/
├── ui/               chrome (вкладки, панель, боковая панель), flyout (меню и панели), страницы mizu://,
│                     общая дизайн-система и перевод (shared/i18n.js)
├── filters/          встроенный список «Mizu Shield – основные трекеры»
└── icons/            значок приложения
```

Всё, кроме `mizu-engine`, Windows-части `mizu-media`, `mizu-setup` и `mizu-browser`, не зависит от платформы и
покрыто модульными тестами.

## Процессы и окна

```
mizu.exe (UI-поток, однопоточная COM-квартира)
 ├── окно браузера (Win32, своя рамка, Mica)
 │    ├── chrome          mizu://chrome/           вкладки, панель, закладки          (доверенное)
 │    ├── боковая панель  mizu://chrome/?sidebar   вертикальные вкладки               (доверенное)
 │    ├── вкладки         по контроллеру WebView2 на вкладку (создаются по требованию) (недоверенное)
 │    ├── запасное окно   заранее созданное пустое представление для мгновенной новой вкладки
 │    └── flyout          mizu://flyout/           меню, панели, запросы               (доверенное)
 ├── скрытое окно сообщений   очередь событий, таймеры, связь с другими экземплярами
 └── рабочие потоки           загрузка и компиляция фильтров, загрузка скриптов, проверка медиа

msedgewebview2.exe (управляет WebView2): браузерный процесс, GPU, сеть, служебные, изолированные рендереры по сайтам
```

Интерфейс браузера тоже написан на HTML, но работает в отдельных представлениях, которые загружают только вшитые файлы
`mizu://`. Веб-содержимое — это нативное дочернее окно, поверх которого HTML рисовать не может. Поэтому меню и
подсказки живут в отдельном всплывающем окне (*flyout*). Оно создаётся один раз на окно браузера и переиспользуется,
так что меню открываются мгновенно.

С вертикальными вкладками тот же документ chrome запускается второй раз — в режиме боковой панели слева от содержимого.
Оба представления получают одно и то же объединённое состояние. Ширина панели — это настройка (160–520 пикселей),
её меняют перетаскиванием края.

Окно показывается, только когда chrome сообщил о готовности (запасной вариант — через 2 секунды), поэтому пустым оно не
мигает. Фокус переводится на страницу только при настоящей активации окна. Реакция на каждое сообщение активации
зацикливала бы фокус.

## Поток событий

1. WebView2 вызывает COM-событие в UI-потоке. `mizu-engine` превращает его в типизированное событие Rust и вызывает
   `ViewHandler` (`mizu-browser::handler::Dispatcher`).
2. **Синхронные решения** принимаются по `hot::Hot` — небольшому состоянию, которое занимается совсем ненадолго:
   - защита навигации;
   - блокировка запросов;
   - добавление заголовков;
   - скрипты документа.
3. Всё остальное ставится в `queue` и обрабатывается из цикла сообщений с монопольным доступом к `App`. Повторный вход
   (например, модальный диалог прокачивает сообщения, пока состояние занято) невозможен по построению: модальные
   диалоги запускаются только из `queue::outside`.
4. Изменения помечают окна «грязными». В конце каждой прокачки браузер отправляет в chrome одно объединённое событие
   `state` на окно.

## Протокол интерфейса

`mizu-ui::protocol` описывает закрытые перечисления всех команд (`{"cmd":"new_tab"}`, `{"rid":3,"cmd":"history_query",…}`)
и событий (`{"type":"state",…}`, `{"type":"reply","rid":3,…}`). Неизвестные или некорректные сообщения не проходят
десериализацию и отбрасываются. Кто и что может отправлять — в [SECURITY.md](SECURITY.md).

## Блокировка контента

```
тексты списков (кеш в profile/filters) ─┐
свои правила ───────────────────────────┼─► FilterSet adblock-rust ─► Engine (+ ресурсы скриптлетов и подмен)
встроенный основной список ─────────────┘           (компилируется в рабочем потоке, подменяется атомарно)

NavigationStarting (верхний уровень) ─► проверка документа (вредоносный → страница предупреждения)
                                     └► косметический CSS + скриптлеты + скрипты ─► AddScriptToExecuteOnDocumentCreated
WebResourceRequested (каждый запрос) ─► check(url, адрес страницы, тип) ─► блок | подмена (data:) | удаление параметров | + Sec-GPC
```

## Сеанс и восстановление после сбоя

Сеанс включает все обычные окна, вкладки, закрепления, стеки закрытых вкладок и положение окон. Он сохраняется в
SQLite раз в несколько секунд, если что-то изменилось, и при выходе.

Пока Mizu работает, существует `running.lock`. Если при запуске файл найден, значит, прошлый запуск завершился сбоем:
Mizu восстанавливает сеанс или показывает кнопку восстановления на новой вкладке. Восстановленные вкладки «ленивые»:
представление движка создаётся, только когда вкладку впервые открывают.

## Пароли

1. Небольшой скрипт перехвата (часть скрипта документа при каждой навигации) замечает отправку формы входа. По каналу
   с токеном он сообщает адрес, логин и пароль.
2. Браузер показывает панель «Сохранить пароль?». Сохранённые секреты шифруются DPAPI (`vault.rs`) и хранятся в
   таблице `logins`.
3. Значок ключа в адресной строке открывает список логинов. Заполнение выполняет скрипт в странице через `ExecuteScript`.

## Правила сайтов для скриптов

У каждого скрипта есть пользовательские правила (`SiteRules` в `mizu-userscripts`): списки «только здесь» и
«никогда здесь».
- Если список «только» не пуст, собственные `@match`/`@include` скрипта не учитываются. `@exclude` скрипта и список
  «никогда» действуют всегда.
- Правило может быть:
  - именем сайта (`youtube.com` — с поддоменами);
  - сайтом с путём (`github.com/user`);
  - обычным шаблоном (`https://*.example.org/*`).

## Перевод

- `shared/i18n.js` содержит русский словарь и несколько регулярных выражений.
- Он переводит текстовые узлы и атрибуты `title`, `placeholder` и `aria-label`, включая содержимое, добавленное
  позже (через `MutationObserver`).
- Отдавая страницу, браузер ставит `data-lang` на `<html>`, поэтому текст переводится до первой отрисовки.
- Данные сайтов помечаются `translate="no"`.

## Обновления

```
TIMER_UPDATE (через 90 с после запуска, затем каждые 6 ч)
  ─► загрузить mizu-update.json и .sig из последнего выпуска на GitHub
  ─► проверить подпись ed25519 (открытый ключ вшит) ─► версия новее?
  ─► установленная копия? ─► загрузить установщик (адрес только из выпусков этого репозитория) ─► проверить SHA-256
  ─► «Перезапустить и обновить» ─► MizuSetup /S --wait-pid <pid> --relaunch
     (ждёт выхода Mizu, заменяет файлы, снова запускает Mizu)
```

Сам обновляется только экземпляр, установленный через MizuSetup (папка записана в записи удаления). Портативная копия
только сообщает о новых версиях. Движок Windows обновляет отдельно, а `mizu://about` показывает обе версии и состояние
обновления.

## Установщик

`mizu-setup` вшивает релизный `mizu.exe` при сборке (`MIZU_SETUP_PAYLOAD`). Его окно — небольшая страница WebView2 без
рамки (`ui.html`); если WebView2 не запускается, используются обычные диалоги Windows. Установщик:
- ставит Mizu для пользователя в выбранную папку и создаёт ярлыки;
- регистрирует Mizu в `HKCU\Software\Clients\StartMenuInternet\Mizu` с ProgID `MizuURL`/`MizuHTML`, чтобы он появился
  в «Приложениях по умолчанию»;
- создаёт запись удаления и копирует себя как `uninstall.exe`.

Запущенный под именем `uninstall.exe`, установщик удаляет Mizu. Он стирает только свои файлы, а папку — только если
она пуста.
