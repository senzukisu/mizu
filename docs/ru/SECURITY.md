# Модель безопасности Mizu

## Сообщения об уязвимостях

Об уязвимостях сообщайте закрыто через GitHub Security Advisories в репозитории, а не в открытых issues.

## Принципы

- Используем песочницу и изоляцию сайтов движка и никогда их не ослабляем.
- Никакой самодельной криптографии:
  - TLS обеспечивают движок и Windows (SChannel);
  - пароли шифрует Windows DPAPI;
  - подписи обновлений проверяет `ed25519-dalek`.
- Веб-содержимое не доверенное. Единственное доверенное веб-содержимое — интерфейс Mizu, и он ничего не загружает из сети.
- По умолчанию «закрыто»: неизвестные сообщения отбрасываются, неизвестные разрешения отклоняются, неверные
  сертификаты не принимаются.

## Процессы и песочница

Страницы работают в процессах рендеринга Chromium: они в песочнице и изолированы по сайтам. Ими управляет среда
WebView2; Mizu не меняет флаги песочницы. Процесс браузера (`mizu.exe`) запускается от обычного пользователя
(`asInvoker`) и сам веб-содержимое не выполняет.

## Уровни доверия

| Поверхность | Содержимое | Может отправлять |
|---|---|---|
| Chrome (`mizu://chrome/`) | Только вшитые файлы | Все команды интерфейса |
| Flyout (`mizu://flyout/`) | Только вшитые файлы | Все команды интерфейса |
| Внутренние страницы (`mizu://settings/` …) | Только вшитые файлы | Команды данных (не команды окон, панелей и запросов) |
| Веб-страницы | Что угодно | Только канал скриптов, подтверждённый токеном страницы |

Уровень доверия определяется по **роли представления** (её знает браузер) **и** по адресу источника сообщения,
который сообщает движок. Веб-страница не может выдать себя за chrome.

## Внутренние страницы

- Они отдаются из файлов, вшитых в программу, поэтому их нельзя изменить правкой файлов на диске.
- Действует строгая CSP: `script-src 'self'`, `connect-src 'none'`, `frame-ancestors 'none'`. Данные сайтов (заголовки,
  адреса) вставляются только через `textContent` и никогда не разбираются как HTML.
- **Защита навигации.** Вкладка может открыть `mizu://`, только если:
  - навигацию начал сам браузер (адресная строка, меню);
  - переход идёт с другой внутренней страницы;
  - это переход «назад/вперёд» или перезагрузка.

  Веб-страницы не могут перейти на внутренние страницы или встроить их во фрейм. `mizu://chrome` и `mizu://flyout`
  нельзя открыть во вкладке вовсе.
- Ресурсы `mizu://`, запрошенные веб-страницами, получают ответ 403.
- Внутренние адреса движка (`edge://`, `chrome://`) и неизвестные схемы запрещены.

## Сеть

- TLS 1.2/1.3 и проверку сертификатов выполняет движок. При ошибке сертификата показывается страница ошибки движка без
  кнопки «всё равно перейти».
- Собственные загрузки Mizu (списки фильтров, скрипты) идут только по HTTPS, через хранилище сертификатов Windows и с
  ограничением размера. Загруженный список проверяется, прежде чем заменить предыдущий.
- Скрипты, запрошенные по `http://`, загружаются по HTTPS.

## Разрешения

Камера, микрофон, местоположение, уведомления, чтение буфера обмена и другие мощные возможности по умолчанию
**запрашиваются**. Решение сохраняется, только если пользователь отметил «Запомнить». Приватные окна держат решения
только в памяти. Движку запрещено сохранять решения самому, поэтому единственный источник правды — список Mizu.
Запросы, которые нельзя точно описать, отклоняются.

## Всплывающие окна и внешние приложения

Всплывающие окна без действия пользователя блокируются. Ссылки на внешние приложения проходят через подтверждение
движка. Схемы, которые использовались для атак (`ms-msdt:`, `search-ms:`, `ms-officecmd:`, `shell:` …), запрещены.

## Скрипты и расширения

- Пользовательские скрипты работают в контексте страницы, как и положено скриптам в стиле Greasemonkey. Их функции
  `GM_*` живут в замыкании, недоступном скриптам страницы.
- Запись сохранённых значений идёт через `chrome.webview.postMessage`:
  - каждое сообщение несёт случайный токен, который существует только внутри замыкания;
  - браузер принимает запись, только если пару «токен — скрипт» он сам выдал этой вкладке;
  - на один скрипт — не больше 4 МБ.
- Перед установкой страница показывает исходный код, сайты, на которых работает скрипт, неподдерживаемые API и
  предупреждение.
- Правила сайтов задаёт сам пользователь; список «никогда» и `@exclude` скрипта действуют всегда.
- Скрипты загружаются только по HTTPS. Ссылки на GitHub, GitLab, Gist и похожие сайты превращаются в адреса «сырых»
  файлов. Автообновление использует `@updateURL`/`@downloadURL`.
- Расширения берутся из выбранного пользователем файла или из Chrome Web Store, когда пользователь нажимает «Добавить в
  Mizu» на странице магазина.
  - Файлы CRX разбираются и распаковываются с защитой от zip-slip и ограничением размера, затем копируются в профиль.
  - В приватных окнах расширения не работают.

## Загрузки

Файлы сохраняет движок, поэтому действуют пометка Mark-of-the-Web и проверка SmartScreen (если включена). Mizu никогда
не открывает загруженный файл сам.

## Локальные данные

Профиль лежит в `%LOCALAPPDATA%` и защищён правами пользователя Windows. Cookies движок хранит в `engine\`; Chromium
шифрует их DPAPI.

## Пароли

- Секреты шифруются `CryptProtectData` (DPAPI, привязка к пользователю Windows) с дополнительной энтропией и хранятся в
  `mizu.db`. Логины и адреса не шифруются, чтобы по списку работал поиск.
- Скрипт перехвата работает в страницах, но может только *предложить* логин. Сообщение должно нести токен страницы, а
  сохраняется оно, только когда пользователь нажмёт «Сохранить» в собственном окне Mizu.
- Логины предлагаются только для того же источника (origin), для которого сохранены, и заполняются, только когда
  пользователь выберет логин.
- Экспорт CSV, как и во всех браузерах, записывает пароли открытым текстом. Mizu предупреждает об этом заранее.
- Собственное сохранение паролей движка выключено, поэтому хранилище паролей одно.

## Обновления

- Манифест выпуска подписан ключом ed25519 Onibi Lab, который хранится вне сети. В программе только открытый ключ.
- Адрес установщика должен начинаться с `https://github.com/senzukisu/mizu/releases/download/`, а его SHA-256 —
  совпадать с подписанным манифестом. Пока обе проверки не пройдены, ничего не запускается.
- Обновление запускается, только когда пользователь выберет «Перезапустить и обновить», от того же пользователя и без
  повышения прав.

## Установщик

- Установщик никогда не просит права администратора. Папку, в которую нельзя писать, он не принимает и объясняет почему.
- Удаление стирает только `mizu.exe`, `uninstall.exe` и их временные копии, а папку — только если она пуста. Поэтому
  даже ошибочно выбранная папка не потеряет чужие файлы. Данные браузера удаляются, только если отмечен этот пункт.

## Поисковые подсказки

- Когда **поисковые подсказки** включены, набираемый в адресной строке текст после паузы в 120 мс отправляется сервису
  подсказок выбранной поисковой системы, и больше никуда.
- Текст, похожий на адрес, не отправляется никогда, а приватные окна не отправляют ничего.
- Поисковые системы без публичного сервиса подсказок остаются без них: Mizu никогда не обращается к другому сервису.
- Подсказки из истории и закладок вычисляются на устройстве.

## Телеметрия

Её нет. Аварийные дампы движка остаются на компьютере: включён собственный сбор отчётов, поэтому Mizu ничего не
отправляет в Microsoft. Учтите, что SmartScreen, если включён, проверяет адреса через сервис Microsoft; в настройке это
объяснено.
